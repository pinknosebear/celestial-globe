## Architecture Rules

### Data pipeline decision tree
- **Stable small reference data**: commit it when practical
- **Large generated static data**: regenerate into `public/` and gitignore it
- **Daily or real-time data**: fetch at runtime
- Current repo state: `npm run build` checks for generated data files and uses them as-is; refresh is explicit via setup / generator scripts
- Architectural split: static star catalog and zodiac line data are generated assets, while future date/location sky state should be computed at runtime
- Moving bodies and true live astronomy data belong in a runtime ephemeris path, not in build-time asset generation

### Coordinate system
- RA in hours -> radians: `ra * pi / 12`
- RA in degrees -> radians: `ra * pi / 180`
- Dec in degrees -> radians: `dec * pi / 180`
- xyz: `x = cos(dec) * cos(ra)`, `y = sin(dec)`, `z = cos(dec) * sin(ra)`
- The same conversion is used across stars, zodiac line vertices, and future boundary work

### Rendering
- All Three.js logic lives in `src/scripts/`
- Astro pages stay thin and only provide DOM scaffolding
- CSS is imported from Astro frontmatter, not linked from `src/`
- Custom shader attribute names avoid Three.js built-in collisions
- Transparent point materials use `depthWrite: false`
- `gl_PointSize` is in screen pixels
- Variable-width lines use `Line2` + `LineMaterial`
- DOM labels use `CSS2DRenderer`

## Key Technical Learnings

### Sky Rotation Problem (Discovered April 2026)
- **Issue**: Planets appeared in wrong zodiac signs relative to actual sky view
- **Root cause**: Hardcoded fixed rotation matrix didn't account for observer latitude, longitude, or Local Sidereal Time (LST)
- **Solution**: Compute LST from UTC + observer longitude, build proper equatorial→horizontal rotation matrix using trigonometry
- **Impact**: Critical for any observational astronomy feature (2D charts, horizon visibility, altitude/azimuth labels)

### Tropical vs Sidereal Coordinates
- **Tropical ecliptic**: Fixed to vernal equinox (~0° in Western astrology), precesses with equinoxes
- **Sidereal ecliptic**: Fixed to actual constellations, offset by ~23-24° from tropical
- **Choice made**: Use `astronomy-engine`'s tropical output (standard for Western astrology charts)
- **Implication**: Planets appear ~1 sign offset from actual constellation boundaries in sky (expected and correct)

### Coordinate System Layers
- **RA/Dec (equatorial)**: Used for 3D globe placement, requires LST rotation for correct horizon alignment
- **Ecliptic longitude (0–360°)**: Used for astrological chart data, zodiac sign determination, chart2txt input
- **Alt/Az (horizontal)**: Used for 2D planisphere charts, requires RA/Dec + LST + observer latitude
- **Conversion path**: All three coexist; no single system is "right" — each serves a different purpose

### Animation Loop vs Async Init Gotcha
- **Problem**: RAF `animate()` started before async `init()` completed, rendering null scene
- **Fix**: Added `isInitialized` flag, animation loop guards on it, `init()` calls `animate()` after loading assets
- **Lesson**: Keep all initialization sequential in a single RAF callback, not split across multiple RAF chains
